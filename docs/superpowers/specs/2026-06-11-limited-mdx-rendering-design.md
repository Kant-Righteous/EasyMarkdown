# 受限 MDX 渲染设计

## 目标

让 EasyMarkdown 在不执行任意 JavaScript 的前提下，正确展示 Z.AI 文档样本中的常用 MDX/JSX 内容，并将应用及安装包版本统一更新为 `1.1.0`。

## 支持范围

### 结构化组件

- `Icon`：渲染内置白名单图标，支持 `icon`、`iconType`、`color`、`size`。
- `CardGroup`：根据 `cols` 生成响应式卡片网格，列数限制为安全范围。
- `Card`：渲染标题、可选图标和内部 Markdown 内容。
- `Tabs`：不提供交互切换，按顺序展开全部 `Tab`。
- `Tab`：渲染为带标题的独立分节，确保预览和 PDF 中内容完整可见。

### HTML

允许样本需要的有限 HTML 标签，包括 `div`、`h3`、`p`、`u`、`img` 和 `video`。属性采用白名单过滤：

- 通用：`class`
- 图片：`src`、`alt`、`width`、`height`
- 视频：`src`、`controls`
- 内联样式：仅允许布局、间距、字号、字重、颜色、圆角和背景等明确列出的 CSS 属性

链接或媒体地址仅允许 `http:`、`https:`；危险协议、事件属性和未识别属性会被移除。

## 明确不支持

- `import`、`export`
- JavaScript 表达式求值
- 事件处理器，例如 `onClick`
- 用户定义组件
- 任意脚本或不在白名单内的 HTML
- Tabs 点击切换

不支持的组件标签不会执行。优先保留其中的可读文本；无法安全解析时按普通文本显示或安全忽略标签。

## 架构

在 `markdown-it` 渲染前增加一个受限 MDX 预处理阶段：

1. 扫描源码并识别白名单组件和标签。
2. 将允许的属性解析为普通数据，不使用 `eval` 或动态代码执行。
3. 把组件转换为带固定 class 的安全 HTML。
4. 由 `markdown-it` 继续处理组件内部及外围 Markdown。
5. 对最终 HTML 做白名单清洗，再交给预览和 PDF 共用。

预览与 PDF 继续调用同一个 `renderMarkdown()`，避免两套渲染结果不一致。

## 图标策略

首期内置样本使用到的图标集合，以固定 SVG 路径或受控图标映射渲染，不加载远程脚本，不允许任意 SVG 内容进入页面。未知图标显示统一占位图标，但不影响标题和正文。

## 样式

- 预览区增加图标、卡片网格、卡片和展开标签页样式。
- PDF 样式提供对应的静态布局，避免分页时丢失内容。
- 卡片网格在窄窗口降为单列。
- 原文指定的白色文字或深色卡片样式会被调整为适配 EasyMarkdown 当前浅色阅读主题，优先保证可读性。

## 安全与降级

- 所有文本和属性值先转义。
- `size`、`cols`、尺寸属性限制数值范围。
- `color` 仅接受安全颜色格式。
- `style` 仅接受属性白名单，并拒绝 `url()`、`expression()` 等内容。
- 标签嵌套不完整时保留可读内容，不执行或拼接脚本。
- 代码块和行内代码中的 MDX 文本保持原样，不参与转换。

## 测试

采用测试先行：

- `Icon` 在标题中渲染且源码标签消失。
- `CardGroup/Card` 生成网格和卡片，内部 Markdown 正常渲染。
- `Tabs/Tab` 全部展开并保留标题与内容。
- 样本所需 HTML 和安全样式可以显示。
- 事件属性、脚本、危险 URL、表达式和未知组件不会执行。
- 代码块中的组件文本保持不变。
- 完整附件样本不再出现已支持组件的源码标签。
- 版本字段均为 `1.1.0`。

最后运行单元测试、TypeScript/Vite 构建，并使用本地浏览器加载完整样本进行视觉检查。

## 预计改动

- 渲染逻辑：`src/markdown.ts`，必要时拆出一个受限 MDX 辅助模块。
- 预览样式：`src/style.css`
- 打印样式：`src/print.css`
- 测试：现有 Markdown 测试或新增专用测试文件、样式测试
- 版本：`package.json`、`package-lock.json`、`src-tauri/tauri.conf.json`、`src-tauri/Cargo.toml`、`src-tauri/Cargo.lock`

不修改 Rust 业务逻辑，不引入完整 MDX 编译器。
